| Data sources | parcial | Formulario host/puerto/BD/SSL, URL manual, guardado con Keychain. Carpetas y colores: en la pestaña General, «Carpeta» (texto libre, un solo nivel; escribir un nombre nuevo la crea y cambiarlo mueve la conexión) y «Color» (siete colores y ninguno) se guardan con la conexión; el explorador lista primero las carpetas por nombre (se pliegan con un clic; el estado no se recuerda) y luego las conexiones sin carpeta, y el color tiñe el icono de la conexión en el explorador, la barra y el diálogo. Faltan carpetas anidadas, arrastrar para mover, plantillas, importar. Pestaña «Opciones» (por motor): solo lectura (las sentencias que no son lecturas se rechazan antes de enviarse, y PostgreSQL, MySQL/MariaDB y SQLite además lo imponen en la sesión); control de transacciones Auto/Manual (no en Cassandra); zona horaria de sesión (PostgreSQL, MySQL, MariaDB, Oracle); consulta de keep-alive cada N s; cerrar la consola tras N s sin uso (la abre de nuevo al ejecutar; no si hay una transacción sin confirmar o un resultado abierto); modo de una sola base de datos (MySQL, MariaDB, Cassandra y, en Oracle, solo el esquema del usuario); script de inicio en cada conexión nueva (tras él se activa el solo lectura); sincronizar el explorador tras un DDL (sí/no) e intervalo de introspección automática en minutos. Se guardan con la conexión. No se hicieron las pestañas SSH/SSL, Esquemas ni Avanzado de DataGrip, ni el nivel de introspección, el modo de sesiones, ni los avisos de DDL desactualizado, que aquí no tienen equivalente. Pestaña «SSH/SSL» · túnel SSH (JSch): host, puerto, usuario y contraseña o clave privada con frase; una sola conexión SSH por servidor intermedio compartida por todas las conexiones a bases de datos que pasan por él (consola, pestañas de tabla, explorador); el host y puerto de General son los que ve el servidor SSH. Un servidor nuevo se confirma con un diálogo la primera vez y su clave se guarda en `~/.ksqlc/known_hosts` (no en el de SSH); si la clave cambia se rechaza sin preguntar. La contraseña o frase va al llavero, no a `connections.json`. No vale con «Solo URL» ni con SQLite, y el volcado nativo no se ofrece con túnel. Sección SSL de la pestaña «SSH/SSL» (sustituye al antiguo «Exigir conexión cifrada»): Desactivado, Cifrado (sin comprobar el certificado), Verificar CA y «CA y host» (también el nombre), con el certificado de la CA y, en PostgreSQL, MySQL y MariaDB, certificado y clave de cliente (PEM; la clave en PKCS#8 o RSA, sin frase de paso). Cada driver recibe lo que lee: PostgreSQL los PEM y la clave en DER, MySQL y SQL Server almacenes Java PKCS#12 y MariaDB la CA en PEM y un almacén para el cliente, todo generado al conectar en archivos temporales con permisos 600. Cassandra solo cifra o no (con el almacén de confianza de Java) y Oracle no tiene SSL (haría falta un listener TCPS y una cartera). Con túnel SSH la comprobación de nombre se hace contra 127.0.0.1. Probado con TLS real en PostgreSQL (incluido el certificado de cliente en ambos formatos de clave), MySQL y MariaDB; SQL Server solo comprueba la traducción a su URL y propiedades. Pestaña «Esquemas»: qué esquemas (bases de datos en MySQL/MariaDB, usuarios en Oracle, keyspaces en Cassandra) lista el explorador: todos, o solo los elegidos de una lista que se lee del servidor con la conexión tal como está en el formulario (incluye los de sistema, que así se pueden elegir aunque estén ocultos), y/o un patrón con `*` y `?` separado por comas. Vale también para el autocompletado y la búsqueda de tablas, y para el modo de una sola base de datos de «Opciones». No se hicieron el esquema actual por defecto ni los filtros por tipo de objeto o por nombre de tabla. |
| Consola SQL | implementado (fase 1) | Sentencia actual / selección / script, cancelación, pestañas de resultados, paginación. Parámetros: `:nombre` (y `?`, salvo en PostgreSQL donde es un operador) abren un diálogo antes de ejecutar, un campo por nombre distinto y uno por cada `?`; el valor se escribe como SQL (`5`, `'texto'`, `NULL`) y se sustituye en el texto, no se enlaza; se recuerda el último valor de cada `:nombre`; no cuentan los textos entre comillas, los comentarios ni los `::`. Explain: dos botones en la barra de la consola (sentencia actual o selección) abren una pestaña «Plan» con el plan como texto alineado. Explain: `EXPLAIN` en PostgreSQL y MySQL/MariaDB, `EXPLAIN QUERY PLAN` en SQLite, `SHOWPLAN_TEXT` en SQL Server (se desactiva siempre al terminar, incluso tras un error) y `EXPLAIN PLAN FOR` + `DBMS_XPLAN` en Oracle; ninguna ejecuta la sentencia. Explain analyze (PostgreSQL, MySQL, MariaDB) sí la ejecuta y pide confirmación si no es una lectura; en SQLite, SQL Server y Oracle no está disponible. Dialecto: el desplegable «Dialecto» de la barra de la consola (automático = el de la conexión) decide cómo se parte el script y qué es un parámetro: en Oracle un bloque PL/SQL termina en una línea `/`; en SQL Server una línea con solo `GO` separa lotes y no se envía; en PostgreSQL `?` no es un parámetro. El resaltado, el formateo y el autocompletado no dependen del dialecto, y Explain sigue usando el motor de la conexión. Modo notebook (botón de la barra de la consola): cada sentencia del texto es una celda editable con su botón de ejecutar y su resultado debajo (las primeras 500 filas, con cuadrícula; filas afectadas o el error). El texto de la consola sigue siendo la única fuente: editar una celda edita el texto, borrar una celda borra su sentencia y «+ Celda» añade una al final; alternar el modo no pierde nada. ⇧↵ o ⌘↵ ejecuta la celda; ▶ y ▶▶ de la barra ejecutan la celda activa o todas (hasta el primer error). Explain actúa sobre la celda activa. Los resultados de las celdas no van a las pestañas de Services. No hay reordenar celdas, ni celdas de texto o Markdown, ni se guardan los resultados al cerrar. |
| Database Explorer | implementado (fase 2) | Árbol perezoso namespace → grupo → objeto → columnas/índices/FK, refresco (manual y tras DDL), filtro, abrir datos con doble clic. Buscar tabla o vista por nombre (⌘⇧O o lupa del explorador): todas las tablas, vistas y vistas materializadas de todos los esquemas leídos, con varias palabras, ordenadas por prefijo del nombre; ↵ abre los datos y ⇧↵ la muestra en el explorador. Mostrar esquemas de sistema (botón del explorador, se recuerda): añade `pg_catalog` e `information_schema` en PostgreSQL, `mysql`, `sys`, `performance_schema` e `information_schema` en MySQL/MariaDB, `sys` e `INFORMATION_SCHEMA` en SQL Server (con las columnas de sus vistas), todos los usuarios en Oracle (`SYS`…), `temp` y las tablas `sqlite_*` en SQLite y los keyspaces `system*` en Cassandra; también entran en el autocompletado. Los niveles de introspección de DataGrip no hacen falta: el árbol ya carga por niveles (esquemas, objetos y después columnas e índices al expandir). Falta buscar dentro del DDL o de rutinas y secuencias. |
| DDL | implementado (fase 2) | Ver/copiar/abrir en consola. Nativo en MySQL/MariaDB (`SHOW CREATE`), SQLite (`sqlite_master`), PostgreSQL (vistas/rutinas nativas, tablas generadas). SQL Server con dialecto nativo (catálogo `sys.*`, corchetes, identity, columnas calculadas, índices con INCLUDE, acciones de claves foráneas, texto original de vistas y rutinas, secuencias; probado contra SQL Server 2022 real; driver mssql-jdbc incluido y opción «Confiar en el certificado del servidor» para certificados autofirmados). Oracle con dialecto nativo (diccionario `ALL_*`, solo esquemas de usuario, identity y columnas virtuales, restricciones e índices, DDL exacto de `DBMS_METADATA` sin almacenamiento; probado contra Oracle Free 23 real; driver ojdbc11 incluido). En Oracle los bloques PL/SQL (`begin`, `declare`, `create procedure|function|package|trigger|type`) terminan en una línea con solo `/`, como en SQL*Plus. |

| Ejecutar rutinas | parcial | «Ejecutar…» en el menú de una rutina del explorador (PostgreSQL, MySQL, MariaDB, SQL Server y Oracle). Genera la llamada con un `:parámetro` por cada entrada y la lanza por la consola, que pide los valores (como SQL: `5`, `'texto'`, `NULL`) y muestra lo que devuelve en pestañas: PostgreSQL `select * from f(…)` para funciones y `call` para procedimientos (con `null` en los OUT; sobrecargas distinguidas por su firma), MySQL/MariaDB `select f(…)` o `call` con variables de sesión para los OUT/INOUT, que se muestran después, SQL Server `select`/`exec @p = …` y Oracle `select … from dual` o un bloque `begin … end;`. SQL Server y Oracle rechazan las rutinas con parámetros de salida. No se hizo en SQLite (no tiene) ni Cassandra, ni depurar rutinas, ni las de paquetes de Oracle. |
| Modificar tabla | parcial | «Modificar…» en el menú de una tabla (solo en conexiones PostgreSQL que no son de solo lectura): diálogo con árbol (tabla, columnas, claves, claves foráneas, índices, checks), formulario de cada nodo y vista previa del SQL. Columnas: nombre, comentario, tipo, not null, valor por defecto, identity con sus opciones y, al crearlas, columna generada. Claves primaria y únicas (diferibles), claves foráneas con `on delete` y `on update`, índices con método, orden, colación, clase de operador, `include` y condición, y checks. Renombrar una columna conserva las claves e índices que la usan. Se aplica todo en una transacción (si algo falla no queda nada), pide confirmación si se pierden datos (quitar columna o cambiar el tipo) y se anota en el historial. Un cambio de definición de una clave, FK, check o índice los quita y los vuelve a crear. Cambiar el tipo de una columna usa `using columna::tipo`; antes se quita el valor por defecto y después se vuelve a poner. No se hizo: INCLUDE en claves primarias o únicas no se modela (una clave cuya definición cambia se recrea sin su INCLUDE); las columnas generadas solo se pueden definir al crear la columna (cambiar la expresión de una ya existente se ignora); dos columnas que intercambian nombre fallan en el servidor (y no queda nada aplicado); no se leen NULLS FIRST/LAST de los índices, opciones de almacenamiento ni tablespace, ni MATCH ni NOT VALID de las claves foráneas ni NO INHERIT de los checks; las restricciones de exclusión no se leen y PostgreSQL las quita sin avisar al quitar una columna; NULLS NOT DISTINCT se pierde cuando se recrea una clave o un índice único; tampoco persistencia, particiones, propietario, permisos, reordenar columnas ni los «virtual» de DataGrip, ni los demás motores (el diálogo y el modelo no dependen del motor; falta leer y generar el SQL de cada uno), ni vistas, secuencias o rutinas. |
